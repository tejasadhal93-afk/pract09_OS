Problem Context: Banking & ATM Transaction Processing

A bank processes ATM withdrawals, deposits, fund transfers, balance inquiries and transaction logging concurrently. Requests arrive from ATMs and branches (producers), wait in a bounded queue, and are executed by transaction-processing threads (consumers). The OS must schedule them on the CPU, allocate memory to each, and grant limited shared resources (DB connections, transaction-service threads, ledger locks) only in a safe state (Banker's Algorithm).
